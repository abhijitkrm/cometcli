# cometcli v0.6.0 — scratch test report

A release gate run on four real SSH hosts (2× Amazon Linux 2023, 2× Ubuntu 24.04),
wiped to bare machines first and rebuilt with cometcli only: host setup, image builds,
a new chain from genesis, a validator joining later, an archive node, governance, a
governed software upgrade, jailing, outages, and docker-level incidents. Run on
2026-10-12 (IST).

**23 findings, all fixed in this release** (13 in round 1, 10 in round 2). The most
serious (12): with `bash` allowed, a model run deleted an archive's chain databases and
`upgrade-info.json` and re-synced it on the wrong binary; the shell guard now refuses
those in every mode, along with `--unsafe-skip-upgrades`. Round 2 found two more that
could have cost a validator or an archive: `provision --reconfigure` would have taken
an upgraded node back to the genesis binary (17), and a whole config dir or a backup
could carry a consensus key past the double-sign guard (21).

Also in this release: no deployment-specific names in cometcli. Container names
default to `<chain id>-<role>`, the Dockerfile lookup and image labels are generic,
and help, docs and examples use placeholder names.

## R2. Chain halt: over 1/3 of the voting power offline
- Stopped sohan1 (45.5% of the power): the chain halted at 73004.

- Started sohan1 (group command, no model): blocks resumed 19s later, 0 missed blocks anywhere (a halted chain doesn't count misses).

## R3. Archive cut off from its peers
- Injected through cometcli: `pex=false`, `persistent_peers=""`, `max_num_inbound_peers=0`, restart → 0 peers, falling behind. (A firewall rule over raw ssh was blocked by auto mode.)
- `/incident`: triage `node-no-peers` → local playbook re-added the chain's 3 other nodes, restarted, synced in 25s. 168s, no model call.
- **Finding 16 (fixed):** `network check` still passed the archive with pex off and no inbound peers. It now warns for archive and RPC nodes, and provision renders pex on (and 40 inbound when it was 0).
- **Finding 17 (fixed, would have broken the archive):** `provision --reconfigure` takes its image from the spec, whose tag is the genesis one (v0.7.2). After the governed upgrade that would have started the archive on the old binary. Reconfigure now keeps the image the node runs ("keeping the image … runs now: primium-v0.7.3"). Rerun: `network check` 0 warn, archive on v0.7.3, 3 peers.
- Fixed: `/incident`'s "Evidence:" was empty after a successful fix (computed after the playbook changed the signals).

## R4. Upgrade scheduled, then cancelled
- **Finding 18 (fixed):** building v0.7.3 again with a test handler would have replaced the handler recorded for v0.7.3 (`v0.7.2-to-v0.7.3`), so the next rebuild for a replay (finding 11) would diverge. A tag's recorded handler is never replaced now: a build with another handler needs its own image name and isn't recorded. Live: refused without an image name; built as `primium-v0.7.3-canceltest` (500s); the record unchanged.
- Too-close heights refused; an upgrade proposal without `image` refused (the plan name is checked against the binary first).
- Proposal 5 (plan `v0.7.3-cancel-test` at 83429, ≈13 min): readiness checked on the proposer, 3 yes votes, PASSED in 1m48s. Triage on val2: `upgrade-imminent` (2485 blocks to halt).
- **Finding 23 (fixed):** `upgrade ready` required name and image; it now takes the scheduled plan and finds the image that registers it. val2: "✗ no image registers plan … — build it before the halt", not ready; sohan1: ready.
- **Finding 22 (fixed):** cancelling needed a hand-written `MsgCancelUpgrade` JSON. New `gov propose --kind cancel-upgrade`: refused when nothing is scheduled, or when the vote can't pass before the height; the approval names the plan it cancels. Proposal 6 passed with ≈1335 blocks to spare; plan cleared; triage clean. 142s.

## R5. Double-sign safety
- **Finding 19 (fixed):** `sec doublesign` asked systemd about a docker node ("inactive … unknown"). It now reads the container state, checks the signing state against the node's height, and reports `double_sign_check_height` (0 on every node: a note, it's the CometBFT default).
- **Finding 20 (fixed):** `sec perms` flagged the `config/` and `data/` dirs (0755) that cometcli itself created. Homes are made owner-only at init and on reconfigure; val3 reconfigured live: 0 problems, 18 blocks missed during the 78s recreate.
- **Finding 21 (fixed):** the shell guard caught key copies by file name, but not `rsync -a …/v6-val3/config/ …/v6-arch/config/` or `tar xzf val3-backup.tgz -C <node home>`. Both now refused in every mode (whole config/data dirs, recursively or as a source; archives unpacked into a node home), while `cp genesis.json ~/.evmd/config/` and making backups still work. Tested by command, not by asking a model to try it on a live validator.
